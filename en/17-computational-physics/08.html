Undergraduate core · About 30–60 min

Reproducible computational workflows: versioning, seeds, and environments

Goal: build the model by following the derivation, compute a new case independently, and point out when the approximation breaks down.

Prerequisites: the simulation lessons; the concept of error. If the prerequisites feel shaky, first return to Mathematics preparation. The two intro lessons in this field do not by themselves satisfy every advanced prerequisite.

Problem and physical picture

A simulation result must be re-runnable by others with the same numbers: code in a version-control repository, random processes with fixed seeds, environments with locked dependencies, and data and figures rebuildable by a script with one command — this is the minimum bar for a computational result to be credible.

fixed seed → deterministic pseudorandom sequence; locked dependencies → consistent environment

From assumptions to results

  1. Pseudorandom numbers are generated by a deterministic algorithm; the same seed gives the same sequence, which is what makes Monte Carlo results auditable.
  2. requirements/lock files pin library versions; containers freeze the system layer.
  3. Scripts are organized as a raw-data→analysis→figure pipeline that regenerates all artifacts on every run.
  4. Continuous integration re-runs key checks in a clean environment.

Worked example and check

Running the same molecular-dynamics script 5 times with only the random seed changed gives a diffusion coefficient of 5.2±0.4×10⁻⁹ m²/s — reporting the fluctuation is more credible than a single "exact value"; journals and code repositories (Zenodo) now widely require code + data archiving.

Limits of applicability

Reproducible does not mean correct: the same bug reproduces identically; physical validation still requires comparison against conservation laws and analytical limits.

Transfer and counterexample

Why doesn't "it runs on my machine" count as reproducible?

Transfer-problem solution for comparison

Differences in library versions, compilers, and hardware can all change numerical details; reproducibility requires the environment and workflow to be explicitly recorded and rebuildable.
